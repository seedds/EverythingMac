# EverythingMac 0.1.60

## Changes

- Editing a file, or changing a folder's permissions, extended attributes, or Finder tags, now updates that item's size and dates in place. Previously the item (for a folder, its entire contents) was removed and scanned again, and the whole search was repeated. Results, row positions, and selections now stay as they are, and the visible rows show the new sizes and dates.
- Adding and deleting files that share a common name, such as index.js or .DS_Store, updates the name index with less work, which makes deleting large folders faster.
- Renaming a file or folder only by letter case, for example Report to report, no longer leaves both names in the index.
- The release workflow uses a current version of the checkout action.

## Performance

Measured on a 4.57-million-entry index with synthetic events for unchanged files:

- A Finder tag or extended-attribute change on Xcode.app (about 167,000 items) took 1.24 s to process and was followed by a 170 ms re-sort; it now takes under 1 ms with no re-sort.
- 10,000 file-edit events took 135–198 ms and forced a full search and a 173 ms re-sort; they now take about 107 ms and keep the current results.

On a synthetic tree, deleting a folder containing 20,000 files with the same name went from 71 ms to 9 ms, and creating 5,000 more went from 95 ms to 75 ms. Index loading and search times are unchanged.

## Validation

- Passed 1,821 Rust tests, with the system-wide search cancellation test excluded, and clippy without warnings.
- Passed the saved-index, sort, selection, feature, live, tab, and terminal checks. The selection check now also accepts a size updated in place without a new search. `--trash-check` times out at step 23, as it does on 0.1.59.

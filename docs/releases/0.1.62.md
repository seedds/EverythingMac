# EverythingMac 0.1.62

## Changes

- Selecting large result lists is much faster and uses less memory. Selected items are tracked by a stable identity instead of building and hashing the full path of every selected row, and the selection is restored after searches and live updates without rebuilding those paths.
- Selections of up to 4,096 items stay selected when a live update scans their folder again.
- After a rescan, only files found in the new index stay selected, so file actions no longer fail because a selected file disappeared during the rescan.
- Quick Look shows up to the first 1,000 selected items. Quick Look, file actions, and dragging no longer check each selected file on the main thread.
- Opening more than 50 items asks for confirmation, as moving more than 50 items to the Trash already does.

## Performance

Measured on a 4.57-million-entry index with every result selected:

- Selecting all results took 2.8 s and 239 MB of memory; it now takes 37 ms and 70 MB.
- Restoring that selection after a new search or live update took 4.1 s; it now takes about 70 ms.
- Preparing Quick Look for the selection took 5.3 s (all 4.57 million paths); it now takes under 1 ms (the first 1,000).
- Restoring a single selected row after a search took 19 ms; it now takes under 2 ms.

Search and index loading are unchanged. The all-files view measured 17–25 ms in both versions, depending on the run, with the same amount of work per search.

## Validation

- Passed 1,826 Rust tests, with the system-wide search cancellation test excluded, and clippy without warnings.
- Passed the saved-index, sort, selection, feature, live, tab, and terminal checks. The live and tab checks now expect Quick Look to keep the selected files up to its 1,000-item limit. `--trash-check` times out at step 23, as it does on 0.1.61.

# EverythingMac 0.1.64

## Changes

- Opening the index is faster and uses less memory. Sort orders are now built by the first search that needs them instead of all six at startup, including one the app never used.
- Saving the index no longer copies it in memory first, so each save pauses searching, scrolling, and selection for less time and needs less extra memory. The saved file format is unchanged.
- The index is saved while idle at most every 10 minutes instead of every minute, and no longer rewritten when only its place in the filesystem event history advanced. A new scan is still saved within about a minute, quitting and switching indexes save everything, and later changes are replayed from macOS filesystem events on the next launch.

## Performance

Measured on a 4.57-million-entry index:

- Opening the index took 2.67 s and 818 MB of memory; it now takes 2.15 s and 538 MB.
- Peak memory while searching fell from about 893 MB to 614 MB unsorted, 684 MB sorted by name, and 788 MB sorted by date.
- The first sorted search after opening builds that column's order once: 167 ms sorted by name and 271 ms sorted by date. Opening plus a first name-sorted search still finishes about 0.4 s sooner. Later searches are unchanged.
- Each index save pauses other work for about 340 ms instead of 415–440 ms and needs 188 MB instead of 334 MB of extra memory.

## Validation

- Passed 1,828 Rust tests, with the system-wide search cancellation test excluded, and clippy without warnings. A new test confirms that saved index files are byte-for-byte identical to those written before.
- Passed the saved-index, sort, selection, feature, live, tab, and terminal checks. `--trash-check` times out at step 23, as it does on 0.1.63.
